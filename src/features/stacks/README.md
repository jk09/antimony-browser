# stacks

Shows each tab's navigation in a card at the top of the assistant panel (apart from the conversation and the prompt, with a focus ring while it has focus) as a vertical, branching tree of breadcrumbs: click any page to go back (or forward) to it without changing the tree, and follow another link to start a branch. Links that open a new tab start a new stack in its own live tab; stacks are named after their first page, switched in the header or with `@name` in the prompt, whose `@` menu also opens any page of any stack (`@name/page`; inside a question the reference attaches the stack's outline or the page for the model) and come back after a restart. A stack whose page plays sound shows a speaker next to its name and in the stack list; a click mutes or unmutes its tab without switching (not remembered after a restart). Buttons at the top reload the selected page (Ctrl/Cmd+R) and open a new stack at the home page (bing.com until `/home` changes or clears it; Ctrl/Cmd+N), which is also where a stack opens at start and after the last one closes; a spare tab waits at the home page in the background, so a new stack shows it at once with the page focused; such a stack is named after the first page reached from it; each page's × closes it with its branch (Ctrl/Cmd+W the selected one). Ctrl/Cmd+E moves focus into the tree on the active page (again, back to the page); in the tree ↑ ↓ Home End move and Escape returns to the page. The search box in the card's top row finds the stack's pages whose title or URL (without scheme) contains every typed word and lists them in place of the tree, matches marked (↑ ↓ select, Enter or a click opens, Escape clears and returns to the tree); typing a character in the tree moves it into the box. Pages imported from Edge arrive as stacks of their own (related pages from one import, by site and topic), unopened and behind yours until you switch to one. Ctrl+Tab returns to the previously used stack; holding Ctrl and pressing Tab again walks older ones in the open list, releasing switches. Switching a stack (any way) focuses its page.

## Entry points
- UI: `ui/StackHeader.tsx` – the panel's `header` slot (`App.tsx`): switcher (`@name ▾`: list, switch, close, New stack; disabled while the assistant runs), sound buttons (🔊/🔇 by the current name and on each listed stack; enabled while the assistant runs), the search box (combobox over a listbox of results), ↻ Reload and + New stack buttons (hints name the shortcuts), the tree with a × per row (Delete on a focused row; disabled while the assistant runs) (at most 8 lines and 35 % of the window; longer trees collapse to root, `⋯ N more`, the rows around the active one) and the full-stack overlay
- IPC: `stacks:state|go-to-node|switch|create|close|close-node|outline|home|set-home|set-muted|pages|open-page` (UI → main; `pages`: every named stack with all its rows and their `ref`s; `open-page`: switch if needed, then go to the node, focusing the page; `outline` takes `name/ref` for one page), `stacks:state-changed` (main → UI, batched per 16 ms), `stacks:command` (main → UI: `reload|new|close-page|focus-tree`, run like the buttons; `cycle-next|cycle-previous|cycle-end|cycle-cancel` for Ctrl+[Shift+]Tab, the UI keeps the most-recently-used snapshot and the highlight) – `ipc.ts`
- Main: `register` in `main.ts` – one stack per navigation tab; applies `onPageEvent` navigations to the tree, starts navigations from nodes (nearest session-history entry via `goToIndex`, else a load), is navigation's history resolver (back = parent, forward = last visited child), restores the current stack's tab at start, else opens one at the home page (also after the last stack closes); File → Reload Page / New Stack / Close Page / Focus Stack (Ctrl/Cmd+R, N, W, E, also caught in `before-input-event` of the chrome UI and every browsing-session webContents, like Ctrl/Cmd+B); a new stack at the home page takes the spare tab (`prepare`d 1 s after the page it follows, replaced at 15 minutes or when the home page changes, not taken if its load failed) and focuses the page; a new stack without a home page opens the prompt; the same new-stack action is the assistant's `new_stack` tool (`provideStackOpener`); `importStacks` (exported for import) adds a chain-shaped stack per group of imported pages, never opens a tab or becomes current, skips groups with 80 % of their pages in an earlier import (`imported` = import time) and stops at 50 stacks; Ctrl+[Shift+]Tab passes through `before-input-event` unconsumed (a consumed key-down makes Chromium drop the key-up of Ctrl, which ends the cycle), Escape cancels, window blur cancels; every switch focuses the shown tab (the hidden view may have held focus, leaving no webContents to receive keys); File → Next/Previous Stack show the keys unregistered and step once
- Shared: `shared/tree.ts` (tree updates, names, page refs, collapse layout, outline, pruning, `removeBranch`), `shared/stored.ts` (`stacks.json` validation), `shared/keys.ts` (shortcuts and their hints), `shared/search.ts` (page search and match ranges)

- Same page (ignoring the fragment) or a known child is reused, never duplicated; reload and replaceState update the active node – `shared/tree.test.ts`
- Names are slugs of the root title (else host), ≤ 32 chars, unique with `-2`…, set once; a stack opened at the home page uses the root's first child – `shared/tree.test.ts › names stacks…`, `› names a stack opened on the new-stack page…`
- With a home page, a stack opens at it at start and after the last stack closes; never for link-opened stacks; files before `version: 2` without a web URL `home` get bing.com – `main.test.ts › opens a new stack at the default home page…`, `› opens nothing at start…`, `shared/stored.test.ts`
- With a home page, one spare tab is kept there and taken by a new stack (also filling an empty one), never shown in stacks state or `stacks.json` before; a failed or over 15-minute-old spare isn't used; changing or clearing the home page replaces or closes it – `main.test.ts › keeps a spare tab…`, `› replaces the spare…`, `› fills an empty current stack…`
- Imported stacks are chains in visit order (a repeat reuses its node), named as given (slug, unique) or like any stack, last used at the group's last visit, unopened, never current; a group mostly imported before isn't imported twice and no own stack is closed to make room – `shared/imported.test.ts`, `main.test.ts › importStacks`
- The collapsed tree never hides the active row – `shared/tree.test.ts › collapses…`, `ui/StackHeader.test.tsx`
- Only the current stack gets a tab at start; others when switched to – `main.test.ts › persists stacks…`
- IPC arguments must name an open stack or a node of the current one (`open-page`: a node of the given stack); the home page is http(s) or null – `main.test.ts › starts a new stack…`, `› opens new stacks at the home page…`, `› lists every stack’s pages…`
- Page refs are the title's slug (else the host's), ≤ 32 chars, unique per stack in tree order; opening the page already shown doesn't reload it – `shared/tree.test.ts › pageRefs`, `main.test.ts › lists every stack’s pages…`
- Closing a page removes its branch; if it held the active page the parent loads; the root closes the stack – `shared/tree.test.ts › removes a branch…`, `main.test.ts › closes a page…`, `e2e/stacks.spec.ts › closes pages…`
- Ctrl+Tab cycles most recent first, wraps, switches on Ctrl up, cancels on Escape or blur, never while the assistant runs; a switch focuses the shown page – `main.test.ts › starts a new stack for a new-tab link and switches…`, `main.test.ts › sends the Ctrl+Tab cycle…`, `ui/StackHeader.test.tsx › cycles through stacks…`, `e2e/stacks.spec.ts › Ctrl+Tab switches…`
- Ctrl/Cmd+E focuses the active row (the search box while searching; from inside the card, returns to the page); search matches every word in the title or the URL past its scheme, over the whole stack, and is kept until cleared; a character typed in the tree starts it – `shared/search.test.ts`, `ui/StackHeader.test.tsx › Ctrl+E and search`
- Ctrl/Cmd+R, N, W, E reach the UI whether the page or the chrome UI has focus; New stack and Close page do nothing while the assistant runs – `main.test.ts › sends Ctrl/Cmd+R…`, `ui/StackHeader.test.tsx › neither closes…`
- Each listed stack's `audio` is `muted` while its tab is muted, `playing` while audible, else null; sound changes publish state without writing `stacks.json`; `stacks:set-muted` takes an open stack and a boolean – `main.test.ts › shows which stacks play sound…`, `ui/StackHeader.test.tsx › shows sound indicators…`
- At most 50 stacks, 500 nodes each (old leaves off the active path go); `/history-clear all` keeps only the current stack's active page – `main.test.ts`, `shared/tree.test.ts › prunes…`

## Dependencies
- Features: navigation (`getTabs` incl. `prepare`/`focus`/`audio`/`setMuted`, `onPageEvent`, `setHistoryResolver` from `main.ts`; `navigation.reload` bridge), history (`onHistoryCleared` from `main.ts`), import calls `importStacks`; agent (`AgentState` type: switching is disabled while it runs; `provideStackOpener` from `main.ts`), prompt (`prompt:open` channel to focus the prompt for an empty new stack); prompt hosts the header and calls this bridge for `@name` and `/home`
- App: `createJsonStore`
- Stored data: `userData/stacks.json` (names, URLs and titles of open stacks' pages, `imported` on stacks made by an import; closing a stack or page deletes it; the home page URL, bing.com when a file older than `version: 2` has none, removed by `/home clear`)

## Security surface
- IPC: the chrome UI reads stacks, their outlines and every stack's pages (titles, URLs), opens any stack's page, loads a stack node's URL (only http(s), checked by navigation), switches, creates and closes stacks, closes pages, mutes or unmutes a stack's tab and sets the home page (http(s) only). By default new stacks load bing.com, so a first start contacts it, and the spare tab fetches the home page in the background (again every 15 minutes); `/home clear` stops both.
- Keys: consumes Ctrl/Cmd+R, N, W and E before web pages see them (and Escape while cycling); sees Ctrl+Tab and the Ctrl key-up without consuming them.
- Web content: – (new-tab handling is navigation's)
